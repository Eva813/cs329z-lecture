RL 的獎勵從哪裡來？ Where does the reward for environments / RL come from? 重點

SFT 的「獎勵」很單純：預測對下一個行動就好。RL 則需要有人判斷結果好不好，來源從可靠但狹窄排到通用但模糊：

來源做法特性
程式測試 Code Tests跑一組單元測試，確定性地檢查最可靠，但只適用能寫測試的任務
評分準則 Rubrics讓 LM 或人逐項檢查一份清單是否滿足較通用，可靠度看清單寫得多好
LM 評審 LM-as-a-Judge模型比較兩個以上的解答並排名更通用，但有模型偏差
人類偏好 Human Preference線上評測，讓真人選出最好的答案最通用，但貴、慢、主觀

越往右越能處理開放式任務，但獎勵也越容易被鑽漏洞（p.68 就是人類偏好被鑽的例子）。獎勵類型與 LM 評審會在三講後詳細討論。

軌跡與環境怎麼拿來訓練 How do we train on trajectories vs. environments?

環境→大量 rollout↗篩選 ⇒ SFT 資料
模仿留下來的↘打分 ⇒ RL 更新
依獎勵加權每次嘗試
  • 同一個環境可以跑很多次 rollout，接著有兩條路：
  • 篩選後做 SFT：只留下成功或品質好的軌跡，讓模型模仿（拒絕取樣式微調就是這種做法）。
  • 打分後做 RL：每次嘗試都保留，用獎勵決定更新時這次嘗試的權重。好的往上推，差的往下壓。

所以環境比軌跡「值錢」：有了環境，兩種訓練方式都能用。

各階段需要多少資料？ How much data at each stage?

  • 實驗室通常不公開。DeepSeek 的 V3（兩年前）和 V3.2（一年前）是少數的資料點：預訓練 14.8T token（V3）、SFT 150 萬筆（V3）、RL 任務 prompt 8.5 萬個（V3.2）。

資料量一路從兆級 token 縮到萬級任務，但每筆的價值和成本一路上升；而算力正往後訓練移動，也就是往 agent 資料移動。

本講重點 Takeaways 重點

  1. Agent 需要的不只是文字：還要任務、環境和軌跡。（PART 1–2）
