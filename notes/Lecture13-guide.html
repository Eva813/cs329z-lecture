從訓練目標到自然語言任務 Modeling / Training Objective → NL tasks

  • p.5 回顧 LM 的基本式：序列機率是每個 token 在「前文條件下」機率的連乘，P(x₁:T) = ∏ P(xₜ | x<ₜ)；訓練目標是交叉熵損失 L = −Σ yᵢ log(pᵢ)，其中 yᵢ 只在正確 token 上為 1。
  • p.6：你當然可以一直訓練到 loss 降不下去為止，但 loss 低不代表 LM 能做真實世界的自然語言任務。

小結：基準是什麼 What is a benchmark? Summary 重點

  • 基準用來衡量 LM 系統的行為或能力是否進步。
  • 基準通常由一組提示（問題、指令、請求）加上一個報告表現的指標組成。
  • 除此之外，基準的形式五花八門：任務類型、預期回應、計分方式都不一樣。
  • 本講剩下的部分和下一講都只談 LM agent 的基準。

為什麼基準重要，以及它的陰暗面

基準帶來測量、方向、共同語言；但一旦變成目標，就會被鑽漏洞。

基準的三個作用 Why are benchmarks important?

p.26：基準不是 NLP 或 AI 獨有的概念。圖例有電腦視覺的 MNIST 與 ImageNet、推薦系統的 Netflix Prize、機器人的 DARPA Grand Challenge，以及科學 ML 的一張結果圖。

  1. 測量：讓實作者能用實驗數據來開發模型、提示和 scaffold。
  2. 方向：讓整個領域聚焦在共同問題上，反映大家集體決定要解決什麼。
  3. 溝通：給研究者共同語言。「X 上 +5 分」對每個人意義相同，不同論文的結果才能比較。

評測協定：跟基準無關的 agent 參數 Evaluation Protocol 重點

這些參數不屬於基準本身，但會大幅影響分數：

  • 嘗試次數：每個任務跑幾次 rollout？
  • 終止條件：最多幾輪、多少牆鐘時間、多少運算預算？還是讓 agent 自己決定何時停？
  • LM 設定：推理強度（reasoning effort）、temperature 等。
  • Harness：固定的，還是自帶（bring-your-own）？允許哪些工具？能不能上網？
  • 彙整與回報：多次執行怎麼合併？要報告哪些面向（成本、輪數、token 數）？

PART 5 的「公平」和「可重現」就是要求你照著這份協定跑，偏離時要說清楚。

什麼是「好」基準？七個性質

挑戰性、自然、鑑別力、容易執行、容易驗證、可解讀、耐用。這些性質彼此拉扯，也會隨模型進步而改變。

52–53

好基準的七個性質 "Good" Benchmarks 重點

  • 七個性質：挑戰性、自然、鑑別力、容易執行、容易驗證、可解讀、耐用。講者說這不是完整清單，還有其他值得考慮的性質。
  • (a) 這些性質之間有天然的張力，例如越自然的任務通常越難自動驗證（見 p.58）。
  • (b) 基準是「活的」軟體，這些性質會隨模型演進而變。圖中用雷達圖比較 SWE-bench 剛推出時（2023）和現在，兩者形狀明顯不同；推出時挑戰性那一軸較高。
  • p.53 的思考方式：基準是一種載具，用來向別人傳達你的模型能做（或不能做）什麼。所以要讓別人盡可能容易執行你的基準。

容易執行 Easy to Run

讓基準能用最少的指令（最好一行）跑起來，避免需要太多步驟才能重現。

  • 用一個腳本設定好所有東西。

誠實：測試集只用來量，不用來調 Honest

原則反例
不要在測試集上調參2015 年 ImageNet 競賽中，一支隊伍因為對測試集提交太多次而被取消資格。
不要挑最好的那次其實跑了 10 次，卻報 pass@1：這等於挑出「最幸運」的那次當結果。
發布你報告的那個系統報的數字要來自你開源的系統。不要用一個變體衝排行榜，再發布另一個。

這是 p.28 Goodhart 定律在「報告」端的版本：把測試分數當目標，分數就不再代表能力。

總結 Summary 重點

  • 要改進 LM agent 系統，就得知道怎麼量它的行為和表現。基準是做這件事的主要工具。
  • 基準在概念上可以拆成三個關鍵組成：題目、環境、指標。
