CWM：先生 300 萬條，再決定留哪些 CWM generated 3M agent trajectories, then decided which ones to keep.

  • Meta FAIR 的 CWM（Code World Model）從 3,150 個 repo、10,200 個 Docker 映像產生了 300 萬條 agent 軌跡。
  • 丟掉近似重複：同一個 repo 內，保留下來的軌跡兩兩之間的 Jaccard 相似度要低於 0.5。
  • 保留失敗的嘗試：CWM 的目標是學一個「程式環境的世界模型」（預測執行程式會發生什麼），所以不依成功與否過濾。失敗的軌跡一樣記錄了環境怎麼反應。

這個例子預告了後面兩個主題：去重（PART 4 的多樣性）和失敗軌跡也有用（PART 3 的 NAT、EEF）。篩選標準取決於訓練目標，沒有一體適用的規則。

Rollout 之後再三道過濾 After rollouts, three more filters.

候選任務→洩漏探測

DAPO：全組同分，RL 就學不到東西 If every rollout in a group gets the same reward, RL learns nothing. 重點

advantage = (reward − 組平均) / 組標準差。一個 prompt 跑 8 次 rollout：

混合1 0 1 1 0 0 1 0 → 平均 0.5，每次 rollout 的 advantage 有正有負 → 學得到
全對1 1 1 1 1 1 1 1 → 每個 reward 都等於平均，分子為 0 → 沒有梯度
  • 這是 GRPO 這類「組內相對比較」演算法的特性：模型只能從「同一題裡做得比較好的那幾次」學習。全對或全錯就沒有比較對象。
  • （補充：全組同分時標準差也是 0，實作上會加一個很小的常數避免除以零，結果 advantage 仍是 0。）
advantage優勢值（這次比平均好多少）group組（同一 prompt 的多次 rollout）gradient梯度

NAT：留下失敗的軌跡，並標記它 NAT (Negative-Aware Training) 圖片頁

  • p.45：一般做法只用成功的軌跡訓練。圖中是一道數學應用題的兩條軌跡（Thought / Action / Observation 交替）：左邊成功；右邊失敗（答 20，正解 90），但前面幾步的推理是合理的，一般做法卻整條丟掉。
  • p.46：NAT 的做法是保留失敗的軌跡，在前綴或後綴加上標記，告訴模型這條成功還是失敗。流程：收集正負軌跡 → 資料清理 → 依正負重新格式化 → 微調 → 推論時要求模型產生「成功」版本。
  • p.47：NAT 的解釋是，失敗的軌跡混合了有用的資訊和錯誤。加上標記，讓模型在「吸收有用資訊」和「學到錯誤」之間取得較好的平衡。

和 CWM（p.7）保留失敗軌跡的理由不同：CWM 是為了學環境的反應，NAT 是為了讓模型分辨好壞行為。
