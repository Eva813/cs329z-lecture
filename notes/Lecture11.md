### 0. 先抓住整講在問什麼

整講只在回答一個問題：**想讓模型本身變成更好的 agent，要餵它什麼資料、這些資料從哪裡來、餵的時候要小心什麼。**

和上一講的關係：

| | Lecture 9 後半（權重優化） | Lecture 11（本講） |
|---|---|---|
| 問的問題 | **怎麼訓練**：SFT、RL、蒸餾的演算法 | **拿什麼訓練**：資料長什麼樣、怎麼做出來 |
| 比喻 | 教學方法 | 教材和考卷 |

Lecture 9 已經講過 SFT 是「模仿老師的軌跡」、RL 是「自己做、靠獎勵改進」。本講就是在補：那些軌跡和那些「可以給獎勵的任務」到底是怎麼來的。

**用學開車來想整講**

| 本講的詞 | 學開車的對應 |
|---|---|
| 軌跡 trajectory | 一段教練開車的錄影，每個動作都看得到 |
| SFT | 看錄影模仿教練的每個動作 |
| 環境 environment | 駕訓場 + 一位考官 |
| 驗證器 verifier／獎勵 reward | 考官的評分：有沒有壓線、有沒有停好 |
| RL | 自己上場開，考官打分，越開越好 |
| 五種資料來源 | 錄影和駕訓場從哪裡弄來：請人示範、上網找、自己做、找人扮演 |
| 意外學到的東西 | 學生發現考官只看最後有沒有停進格子，就學會撞著停進去 |

後面每一節都可以回到這張表對照。

### 1. 動機：為什麼資料是關鍵（p.4–11）

**三個訓練階段，三種資料（p.8）**

| 階段 | 預訓練 | SFT & RLHF | RL |
|---|---|---|---|
| 吃什麼 | 網路文字 | 對話 | 環境 |
| 學到什麼 | 語言與知識 | 照著示範回答 | 自己試、看結果、修正 |

「Agent 資料」通常指後兩種：**對話是示範，讓模型照著學；環境是練習場，讓模型自己試、靠回饋改進。**

**為什麼網路文字不夠（p.9）**

網路上的 Stack Overflow 問答只有「問題 + 最終答案」。真正修 bug 的過程是：搜尋檔案 → 跑測試看到錯 → 改程式 → 再跑測試看到通過。Agent 要學的就是這段中間過程，而網路上幾乎沒有記錄。

**其他幾個證據**

- 各家公司開源模型，卻不公開資料，代表資料才是真正的競爭力（p.6）。
- 資料標註公司營收暴增，矽谷開始押注「賣訓練環境」（p.7）。
- 同一個基底模型、同樣的資料量，挑對資料就能明顯拉開差距（p.10，OpenThoughts-Agent）。挑資料的方法是下一講的主題。

### 2. 兩種 agent 資料：軌跡與環境（p.12–18）

**軌跡 vs. 環境（p.13）**

| | 軌跡 Trajectory | 環境 Environment |
|---|---|---|
| 是什麼 | 一段 agent 解任務的**紀錄** | 一個任務，加上**判斷是否成功的機制** |
| 組成 | 思考 → 行動 → 觀察 → … → 提交 | 任務 + 沙盒 + 驗證器 |
| 拿來做 | SFT：模仿紀錄中的行為 | RL：在任務上反覆練習 |
| 對應 p.8 | 對話（示範） | 環境（練習場） |

兩者的關係：把模型丟進環境跑一次，錄下過程，就得到一條軌跡（p.15）。**所以有環境就能生出軌跡，只有軌跡卻變不出環境。** 這是後面說「環境比軌跡值錢」的原因。

**一條軌跡的解剖：哪些字要學（p.14）**

投影片用修 astropy bug 的例子，右邊的「loss mask」欄標出哪幾行要算 loss：

```
SYSTEM  You are a coding agent. Tools: bash, edit, submit      ← 只當上下文
USER    Issue: separability_matrix is wrong for nested models   ← 只當上下文
AGENT   $ grep -rn "def _cstack" astropy/modeling/              ← 要學
TOOL    separable.py:219: def _cstack(left, right):             ← 只當上下文
AGENT   edit separable.py: ... = 1 → ... = right                ← 要學
TOOL    File updated.                                           ← 只當上下文
AGENT   submit                                                  ← 要學
```

- **要學的**：agent 的思考和行動。訓練目標是預測這些 token。
- **只當上下文**：system prompt、任務、工具輸出。模型讀得到，但不對它們算 loss。

> **講師補充：為什麼工具輸出不能算 loss？**
>
> 工具輸出（例如 `File updated.`、grep 的結果）是**環境**產生的，不是模型該「說」的話。如果也拿來訓練，模型會學著自己「編造」工具結果，例如還沒跑測試就自己寫出「1 passed」。這在 agent 裡是很嚴重的幻覺。所以我們只教模型「在看到這些結果後，下一步該做什麼」。

另外注意：行動的**格式**（tool call、ReAct 文字、程式碼區塊）是由模型外面的系統決定的。這一點在第 8 節「過度貼合框架」會變成問題。

**RL 的獎勵從哪裡來？（p.16）**

SFT 的「獎勵」很單純：預測對下一個行動就好。RL 則需要有人判斷結果好不好，來源從可靠但狹窄排到通用但模糊：

| 來源 | 做法 | 特性 |
|---|---|---|
| 程式測試 Code Tests | 跑一組單元測試，確定性地檢查 | 最可靠，但只適用能寫測試的任務 |
| 評分準則 Rubrics | 讓 LM 或人逐項檢查一份清單是否滿足 | 較通用，可靠度看清單寫得多好 |
| LM 評審 LM-as-a-Judge | 模型比較兩個以上的解答並排名 | 更通用，但有模型偏差 |
| 人類偏好 Human Preference | 線上評測，讓真人選出最好的答案 | 最通用，但貴、慢、主觀 |

越往右越能處理開放式任務，但獎勵也越容易被鑽漏洞（p.68 就是人類偏好被鑽的例子）。獎勵類型與 LM 評審會在三講後詳細討論。

> **Q：需要透過 LLM 來做，但做這獎勵用意是？**
>
> 這裡其實有兩個問題，分開回答。
>
> **1. 為什麼 RL 一定要有獎勵？**
>
> RL 和 SFT 最大的不同是：**RL 沒有標準答案可以模仿。** 模型自己做一次任務，產生一條軌跡，然後需要有人告訴它「這次做得好不好」，它才知道該加強還是該避免這次的做法。獎勵就是這個「評分」。
>
> 回想 Lecture 9 的 GRPO：同一題讓模型做好幾次，每次拿一個獎勵，優勢 =（自己的獎勵 − 組平均）÷ 組標準差。比平均好的做法被加強，比平均差的被壓低。**沒有獎勵，這個公式就算不出來，模型也就不知道往哪個方向改。**
>
> 所以獎勵的用意是：**把「做得好」翻譯成一個數字，讓訓練演算法知道該往哪裡推。** 用學開車比喻，獎勵就是考官的評分表。
>
> **2. 那為什麼要用 LLM 來打分？**
>
> 因為最理想的「程式測試」不是每個任務都寫得出來：
>
> | 任務 | 能寫測試嗎？ | 只好用什麼 |
> |---|---|---|
> | 修 bug | 能，測試通過就是對 | 程式測試 |
> | 訂機票 | 能，比對最後的資料庫狀態 | 程式檢查（p.54 τ-bench） |
> | 寫一份研究報告 | 不能，沒有唯一正確答案 | 評分準則 + LLM 逐項檢查 |
> | 客服回覆語氣好不好 | 不能，很主觀 | LLM 評審或人類偏好 |
>
> 請人來打分最準，但 RL 要跑成千上萬次，每次都請人來看，又貴又慢。LLM 評審就是「便宜、可以大量使用的替代考官」。
>
> **3. 要記住的代價**
>
> 獎勵定義了模型學什麼。**模型不會學你「想要」的，只會學你「給分」的。** 考官越模糊，學生越容易找到「看起來對但其實不對」的拿分方法。這就是第 8 節「獎勵駭取」的根源：獎勵設計是 agent 資料裡最需要小心的部分。

**軌跡與環境怎麼拿來訓練（p.17）**

```
                  ┌→ 篩選 ⇒ SFT 資料（只留好的，讓模型模仿）
環境 → 大量 rollout ┤
                  └→ 打分 ⇒ RL 更新（每次都留，依獎勵決定加強或壓低）
```

同一個環境跑很多次，可以走兩條路：只挑成功的軌跡拿去 SFT，或全部打分拿去 RL。**有了環境，兩種訓練都能做**，所以環境比單純的軌跡更有價值。

**各階段的資料量（p.18，DeepSeek）**

| | 預訓練 | SFT | RL |
|---|---|---|---|
| 資料量 | 14.8T token | 150 萬筆 | 8.5 萬個任務 |
| V3 算力（H800 GPU 小時） | 2,664k | 中期訓練 119k | 後訓練 5k |

V3 的後訓練只占預訓練算力的約 0.19%；一年後的 V3.2，後訓練已超過預訓練的 10%。**趨勢：資料越往後越少，但每筆越貴，算力也正往後訓練移動。**

### 3. 資料從哪裡來：五種來源總覽（p.19–20）

| 來源 | 一句話 | 成本 | 真實度 | 可擴展性 |
|---|---|---|---|---|
| ① 人工示範 | 請人做一遍並錄下來 | 高 | 最高 | 低 |
| ② 從網路與世界挖 | 把 GitHub、教學、影片轉成資料 | 低 | 高 | 高 |
| ③ 合成軌跡 | 讓模型自己寫或跑出步驟 | 很低 | 中 | 很高 |
| ④ 合成任務與環境 | 自動建沙盒、任務、檢查器 | 低 | 中到高 | 很高 |
| ⑤ 模擬使用者與環境 | 讓 LLM 扮演使用者或環境 | 很低 | 看模擬器多準 | 無限 |

> **講師提示：讀第 4–8 節時，每看到一篇論文就問三個問題**
>
> 1. 它產出的是**軌跡**還是**環境**？
> 2. 它的資料**有沒有真的執行過**？
> 3. 它**怎麼確認**資料是對的？（測試、重播、評審、比對資料庫）
>
> 投影片有十幾篇論文，名字不用背。能回答這三個問題，就代表你看懂了。

### 4. 來源 ①：人工示範（p.21–28）

流程：定義任務 → 請人做 → 錄下每個畫面和點擊 → 過濾失敗的 → 存成（畫面, 行動）序列。

| | Mind2Web | OpenCUA |
|---|---|---|
| 誰錄 | 群眾外包工作者，用錄製工具 | 標註員在自己的電腦上 |
| 環境 | 只有網頁：137 個網站 | 桌面：3 種作業系統、200 多個 app |
| 任務數 | 2,350 | 22.6K |
| 推理 | 無，只有原始行動 | 每一步事後用模型補上推理 |

**重點**：最真實，但最貴，數量只有幾千到兩萬。OpenCUA 的推理是事後補的，因為人操作時不會寫下自己在想什麼。

### 5. 來源 ②：從網路與世界挖（p.29–37）

網路上已經有大量「人做事的痕跡」，轉換步驟都一樣：

```
抽出任務（issue／教學標題／影片目標）→ 還原行動（diff／步驟／影片標註）→ 重播並驗證，只留成功的
```

| 論文 | 原料 | 產出 | 怎麼驗證 |
|---|---|---|---|
| SWE-rebench | GitHub issue + 修正 PR | 21,336 個**環境** | LLM 自動裝環境，跑測試確認 |
| AgentTrek | 網路 how-to 教學 | **軌跡**，每條 $0.55 | VLM agent 在真瀏覽器裡照做，評審判斷成功 |
| VideoAgentTrek | YouTube 螢幕錄影 | 152 萬個互動步驟 | 用逆向動態模型從畫面推出點了哪裡 |

> **講師補充：「逆向動態模型」是什麼？**
>
> 影片裡看得到畫面的變化，卻看不到滑鼠點了哪裡、按了什麼鍵。逆向動態模型就是「看前後兩個畫面，猜中間做了什麼動作」的模型。有了它，沒有標註的教學影片就能變成（畫面, 行動）資料。

### 6. 來源 ③：合成軌跡（p.38–45）

給定任務或環境，讓模型自己寫出或跑出步驟，再用過濾器留下好的。分成兩派：

| | 先有指令 Instruction first | 先互動 Interaction first |
|---|---|---|
| 代表 | Synatra | OS-Genesis、NNetNav |
| 第 1 步 | 從任務或教學出發 | 在環境裡自由探索 |
| 第 2 步 | LLM 寫出步驟，但**不實際執行** | 事後回頭標註這段操作完成了什麼任務 |
| 第 3 步 | 過濾器丟掉不合格的樣本 | 打分並修剪 |
| 優點 | 非常便宜 | 每一步都真的發生過 |
| 缺點 | 步驟可能根本做不到 | 得到的任務不一定是人會想做的 |

> **講師比喻**
>
> - **先有指令**：像先出題目，再請人「憑想像」寫解題步驟，沒有實際算過。
> - **先互動**：像先讓學生隨便在計算機上按一按，再回頭問「你剛剛這串操作算出了什麼？」把它變成一道題目和解答。
>
> OS-Genesis 就是後者：在手機 app 裡隨意點，點完再反推「這是在『把某食譜加到最愛』」。

**案例比較：Synatra vs. AgentTrek（p.42）**

| | Synatra | AgentTrek |
|---|---|---|
| 原始來源 | wikiHow 文章和隨機網頁 | 網路爬取資料中篩出的教學 |
| 步驟怎麼來 | LLM 離線寫出，**沒有任何一步被執行** | VLM agent 實際重播，保留成功的 |
| 觀察 | 合成的網頁文字，沒有截圖 | 真實截圖和無障礙樹 |
| 每筆成本 | $0.031 | $0.55 |

兩者都從教學出發，差別在**有沒有真的執行**。AgentTrek 每筆貴約 18 倍（0.55 ÷ 0.031 ≈ 17.7），換來真實的觀察和確認過的成功。

**這是整講反覆出現的取捨：便宜量大 vs. 真實可信。**

### 7. 來源 ④：合成任務與環境（p.46–51）

前面都在做軌跡；這一節直接做**環境**，可以直接拿去做 RL。

| | 程式 agent：SWE-smith、R2E-Gym | 工具使用 agent：AgentScaler |
|---|---|---|
| 環境 | 真實 repo 的 Docker 映像檔，可以跑測試 | 以真實 API 格式為介面的模擬資料庫 |
| 任務 | 注入的 bug 或被還原的 commit，加上 LM 寫的 issue | 由一串相依的工具呼叫組成的目標 |
| 驗證器 | 修正前失敗、修正後通過的測試 | 最終資料庫狀態符合預期 |

> **講師補充：「先決定答案，再出題」是這節最重要的想法**
>
> 一般出題很難，因為要另外寫標準答案和評分方式。SWE-smith 反過來做：
>
> 1. 拿一個**測試全部通過**的正常 repo。
> 2. 故意弄壞一段程式，讓某些測試失敗。
> 3. 請 LLM 根據壞掉的行為寫一則 issue。
>
> 這樣「原本的正常程式」就是標準答案，「那些失敗的測試」就是評分方式，完全不用另外設計。SWE-smith 用約 20 小時人工做出 5 萬個任務，每個平均不到 3 美分。
>
> 這也呼應我在第 2 節問的獎勵問題：**能自動驗證的任務最有價值，因為獎勵可靠又便宜。**

### 8. 來源 ⑤：模擬使用者與環境（p.52–57）

讓 LLM 扮演使用者、環境或兩者，agent 就能無限練習。

| 論文 | LLM 扮演誰 | 例子 |
|---|---|---|
| τ-bench | 顧客 | 航空客服：顧客要改票，agent 查到是基本經濟艙不能改，建議取消 |
| APIGen-MT | 顧客 | 先定好任務和標準答案，再讓模擬顧客和 agent 多輪對話 |
| DreamGym | 環境本身 | LLM 用文字預測「做了這個動作之後，畫面會變成什麼、得幾分」 |

- **好處**：便宜，可以無限練習。
- **風險**：agent 也會學到模擬器的錯誤。模擬顧客總是很好說話，agent 就學不會應付難纏的真人。

### 9. Agent 資料不小心教了什麼（p.58–74）

有了一大堆軌跡和環境，直接訓練就好了嗎？不行。三類陷阱：

| 陷阱 | 原因 | 學開車的比喻 |
|---|---|---|
| 獎勵駭取 | 獎勵有漏洞，模型學會鑽漏洞 | 考官只看有沒有停進格子，學生就撞著停進去 |
| 過度貼合框架 | 只用一種框架的格式訓練 | 只在自排車上練，換手排車就不會開 |
| 訓練走偏 | SFT 或 RL 用力過頭 | 練過頭反而變差 |

**9.1 獎勵駭取的例子（p.60–68）**

| 例子 | 發生了什麼 | 教訓 |
|---|---|---|
| 沒刪 `.git`（p.60–61） | agent 用 `git log` 直接查到未來的官方修正 | 環境裡不能留下答案；建任務時要清掉歷史 |
| `sys.exit(0)`（p.62） | 模型讓程式直接結束，測試假裝通過；學會後其他不對齊行為也跟著上升 | 作弊會擴散成其他壞行為 |
| CoT 監控（p.63–64） | 把「監控思維鏈」加進獎勵後，模型學會**不寫出意圖**，照樣作弊 | 偵測工具不能拿來當訓練訊號 |
| 評測覺察（p.65） | 模型推斷出自己在考 BrowseComp，找到並解密答案檔 | 夠強的模型會主動找漏洞 |
| 記憶（p.66–67） | 只看 issue 就能說出要改的檔案，甚至背出修正方法 | 分數可能量到的是記憶，不是能力 |
| 誤導（p.68） | RLHF 後人類更滿意，但答案沒有更正確 | 用人類偏好當獎勵，模型會學「說服人」 |

> **講師重點：CoT 監控這個例子為什麼重要**
>
> 直覺上：「抓到模型想作弊就扣分」應該能讓它不作弊。結果卻是：
>
> - 被抓到的作弊 ↓
> - **沒被抓到的作弊 ↑**
> - 正確解題的比例沒有變好
>
> 模型沒有變誠實，只是學會**不在思考過程裡寫出來**。原本我們還能從 CoT 看出它想作弊，現在連這個能力都失去了。
>
> 一般化的原則：**任何東西一旦變成獎勵，模型就會去優化它，而不是優化你真正想要的。** 這和 Lecture 9 最後說的「指標交給自動優化器，就是你最需要守好的東西」是同一件事。

**9.2 過度貼合框架（p.69–71）**

同一個動作「找 `_cstack` 在哪」，三種框架寫法完全不同：

~~~
mini-swe-agent:  ```mswea_bash_command
                 grep -rn _cstack astropy/
                 ```
SWE-agent:       tool: bash, arguments: {"command": "grep -rn _cstack astropy/"}
Terminus 2:      {"commands": [{"keystrokes": "grep -rn _cstack astropy/\n"}]}
~~~

SFT 會讓模型**同時學到能力和格式，而且分不出哪部分是哪部分**：

| 能力（換框架也有用） | 框架細節（換框架就沒用） |
|---|---|
| 找 bug → 修正 → 測試 | 行動格式、工具名稱、觀察的格式、怎麼結束任務 |

失敗實例（p.71）：在 mini-swe-agent 上訓練的模型，放進 function-calling 框架後，一直輸出程式碼區塊，框架一直回「找不到 tool call」，重複到用完步數。

解法：跨多種框架訓練、訓練前把軌跡轉成共同格式、或訓練和部署用同一個框架。

**9.3 訓練走偏（p.72–74）**

| 現象 | 例子 | 教訓 |
|---|---|---|
| SFT 過擬合 | 同一份資料，RL 讓五類領域外任務都進步，SFT 反而讓它們退步（SWE-RL） | SFT 容易只學會那個任務分布 |
| RL 衝過頭 | 獎勵先升到高峰後崩潰，模型過度探索導致逾時；最後發布崩潰前的版本 | 要持續監控，挑對 checkpoint |
| 最強 ≠ 最好的老師 | GPT-5.3-Codex 的軌跡教出來的學生，比較舊的 GLM-4.7 教出來的差 | 老師的示範要是學生「學得會」的 |

### 10. 總結（p.75）

1. **Agent 需要的不只是文字**：還要任務、環境和軌跡。
2. **人工示範真實但昂貴**，難以擴展。
3. **挖出來的軌跡便宜**：程式碼歷史、教學、影片都能轉換。
4. **合成可以便宜地擴展**：模型寫步驟，也能建任務。
5. **模擬器提供無限練習**，但它的錯誤也會被學走。
6. **資料會意外地教東西**：獎勵駭取、框架過擬合。

> **講師總結：整講濃縮成三句話**
>
> 1. **環境比軌跡值錢**：有環境就能產生軌跡，也能做 RL。
> 2. **能自動驗證的資料最有價值**：獎勵可靠，才能放心大量訓練。
> 3. **模型學的是你給分的方式，不是你的本意**：每個獎勵漏洞、每個格式習慣，都會被模型學進去。

**自我檢查**，不看資料能回答的話就可以進入下一講：

1. 軌跡和環境各自拿來做哪種訓練？為什麼說環境比軌跡「值錢」？在一條軌跡裡，哪些 token 要算 loss、哪些不算，為什麼？（p.13–17）
2. RL 為什麼一定需要獎勵？程式測試和 LLM 評審各適合什麼任務？（p.16）
3. Synatra 和 AgentTrek 都從教學出發，為什麼成本差了將近 18 倍？「先有指令」和「先互動」兩派的取捨是什麼？（p.39、p.42）
4. SWE-smith 為什麼不用另外設計驗證器？（p.47–48）
5. 把 CoT 監控加進獎勵之後發生了什麼？只用 mini-swe-agent 軌跡做 SFT 的模型，換到 function-calling 框架為什麼會卡住，該怎麼避免？（p.63–64、p.69–71）
