上下文優化還有必要嗎？ Is (Context) Optimization Necessary?

  • 常見質疑：還需要調 prompt 嗎？模型不是規模一大就自然變好？
  • 回答：優化的價值在最後一哩的調適。模型提供很好的通用解，一旦知道你的確切場景，就能針對細節再調整。

什麼時候該優化 When to Optimize 重點

  • 你有符合自己領域的資料和評測。
  • 有些需求很難完整寫進 prompt 或系統設計，但可以用例子和回饋傳達。
  • 有時好的評測比文字更能表達意圖，這時就把系統調到符合你的評測。
  • 系統元件很多、很複雜，手動調不動。

第三點和 Lecture 6（評測）呼應：寫出好的評測，本身就是在寫規格。

優化的好處 Benefits of Optimization

  • 更可靠：減少反覆出現的錯誤，提高不同任務間的一致性。
  • 領域調適：在專門任務、流程與需求上表現更好。
  • 更低成本與延遲：用更小的模型、更短的 prompt 或更少的工具呼叫維持品質。
  • 從經驗學習：把成功軌跡和失敗回饋變成持久的改進。
  • 適應變化：模型、工具和任務需求改變時，能跟著調整行為。

同樣四個範例換個順序，準確率可能差很多。Lu et al. 的做法是不用標註資料就挑出好順序：

列舉範例排列
Train 1–4 的各種順序→讓模型自己生成
一組探測集 probing set→用每種順序預測探測集
看標籤分佈→挑熵高的順序
  • p.15：探測集的句子和標籤都是模型自己生成的；評分時不看探測集的正確答案，只看預測分佈。（投影片把這頁的圖片出處標成 GPT-3 論文，但圖其實來自 Lu et al.，arXiv 2104.08786。）
  • p.16 全域熵：整個探測集的預測標籤分佈。四句預測成 0、0、1、1 是高熵；全部預測成 0 是低熵，代表這個順序讓模型偏向某一類，是壞順序。
  • p.17 局部熵：對每一句看模型在各標籤上的機率，再對探測集取平均。機率分得較開的是高熵、極度篤定的是低熵；同樣偏好高熵順序，避免過度自信的排列。
  • p.18 結果表（11 個分類資料集 × GPT-2 0.1B 到 GPT-3 175B）：用 GlobalE／LocalE 挑順序，大多比隨機順序好，並接近 Oracle（在開發集上試遍所有順序選最好的）。例：GPT-2 0.8B 在 SST-2 上，隨機 74.5 → GlobalE 84.8，Oracle 88.9。

步驟 ②（上）：程式與資料的背景 Grounded Instruction Proposal: Program-Aware · Data-Aware Grounding

提出指令前，先蒐集任務的各種細節交給「提案用的 LM」，讓它寫出有根據的指令。前兩種背景：

  • 1. 程式背景（p.36–38）：讓 LM 讀程式碼，寫出摘要。例：「這個程式要根據花瓣和萼片的尺寸，把鳶尾花分成 setosa、versicolour、virginica 三種，並用語言模型逐步推理尺寸來預測。」
  • 2. 資料背景（p.39–40）：讓 LM 看訓練資料表，寫出資料摘要。例：「資料有三類，各類在花瓣長寬上分佈明顯不同；萼片長寬的趨勢較不明顯。species 欄位和答案重複，沒有額外資訊。」

注意 p.40 的資料摘要結尾還留著「這樣對嗎？我可以改進嗎？」，這是 LM 原始輸出的樣子，投影片沒有修掉。

41–43

步驟 ②（中）：成功的自舉軌跡 Successful Bootstrapped Program Traces

  • p.41 列出兩次呼叫：classify_iris(5.1, 3.5, 1.4, 0.2) → 「versicolor」，以及 classify_iris(5.1, 1.8, 5.9, 3.0) → 「verginica」。第一筆其實是 setosa 的資料（對照 p.39 表的第一列），所以答錯；p.42 只留下第二筆。
  • p.43 展開留下的那筆軌跡：推理說「花瓣長 5.1 比 setosa（通常約 4.8）長、寬 1.8 比 setosa（通常約 1.5）寬……萼片 5.9 和 3.0 比較像 virginica」，答案寫成「virginia」。

這頁的推理其實有錯：setosa 的花瓣長通常約 1.5 cm、寬約 0.2 cm，4.8 和 1.5 比較接近 versicolor；答案也拼錯了。它能留下來，是因為指標只檢查最後答案。這正好說明自舉法的弱點：過濾只看結果，不保證推理正確。

步驟 ②（下）：提示技巧與產生的指令 Prompting Tips · Instructions

  • 4. 提示技巧（p.44）：每次隨機給提案 LM 一條技巧，例如「大膽發揮創意」「在指令中加入一個高風險情境，讓模型必須解出任務」「給模型一個和任務相關的角色（You are a…）」「保持指令清楚簡潔」。
  • p.45：程式摘要、資料摘要、成功軌跡、技巧四樣一起送進提案 LM，產出候選指令。
  • p.46–47 產生的候選指令，例如：
候選 1用提供的花瓣長寬、萼片長寬（cm）準確預測鳶尾花品種，拯救一個極度瀕危的物種免於滅絕。
候選 2給定花瓣與萼片尺寸，預測品種（setosa、versicolour 或 virginica），並依測量值提供逐步推理。
候選 3在一種稀有鳶尾花瀕臨滅絕的危急情況下，根據花瓣與萼片尺寸預測品種以拯救它。

候選 1、3 就是「高風險情境」技巧的產物。哪一條比較好，交給步驟 ③ 的搜尋決定。

優化後的模組長什麼樣 Example Optimized Module

KL(πθ ‖ πteacher) ＝ Ex~πθ [ log πθ(xt+1|x1..t) − log πteacher(xt+1|x1..t) ]

  • 期望值是對學生自己抽樣出的回答取的。

用 agent 做優化：小結 Optimization with Agents Summary 重點

  • agent 是相當有能力的優化器。
  • 把它放進一個能記錄結果、發想點子、實際執行的環境，凡是跑在軟體上的東西它都能優化得不錯。
  • 指標與評測因此成為最需要掌控的部分。

這一點把全講串起來：不管是 GEPA、RL 還是 autoresearch，優化器都會照著指標走，指標寫錯，它就會很有效率地往錯的方向優化。
