整講的主線：**要優化一個 AI 系統，資料、系統、評測指標三樣缺一不可（p.8）；而指標一旦交給自動優化器，就是你最需要守好的東西（p.116）。**

| | 上下文優化 Context Optimization | 權重優化 Weight Optimization |
|---|---|---|

### 1. 優化的條件（p.7–11）

**AI 系統的三根支柱（p.8）**

| 資料 Data | 系統或模型 System or Model | 評測與指標 Evaluation + Metric |
|---|---|---|
| 訓練資料、rollout（實際執行軌跡）、示範、人類回饋…… | 語言模型、複合 AI 系統／workflow、agent 系統…… | 通過率、完全比對、LLM 評審、成本／延遲…… |

要優化一個 AI 系統，三樣都要有。後面每個演算法都可以用這三格去拆：它吃什麼資料、改系統的哪個部分（prompt 還是權重）、用什麼指標判斷變好。

**什麼時候該優化（p.10）**

- 你有符合自己領域的資料和評測。
- 有些需求很難完整寫進 prompt 或系統設計，但可以用例子和回饋傳達。
- 有時好的評測比文字更能表達意圖，這時就把系統調到符合你的評測。
- 系統元件很多、很複雜，手動調不動。

第三點和 Lecture 6（評測）呼應：寫出好的評測，本身就是在寫規格。

> **Q：所以要判斷什麼時候優化 prompt？評測也是需要放入 prompt？**
>
> 分兩件事回答。
>
> **1. 這四點是「要不要優化」，不是「優化 prompt 還是權重」。** 四點講的是整個系統值不值得自動優化，答案是「有」之後，才輪到選上下文優化還是權重優化，那個判準在 p.121–122（本筆記第 6 節）。
>
> **2. 評測不放進系統的 prompt，它在優化器那一側。** 優化的流程是：
>
> 1. 優化器提出一個候選 prompt。
> 2. 系統用這個 prompt 跑訓練資料。
> 3. **指標**在系統外面替輸出打分。
> 4. 優化器依分數決定留哪個 prompt，再提下一個。
>
> 被優化的模型從頭到尾看不到指標。「用評測表達意圖」的意思是：你不必把「我要什麼」一字一句寫進 prompt，只要寫出能判斷輸出好壞的指標，讓優化器去找分數高的 prompt。p.63 的鳶尾花例子就是這樣：沒有人寫「加一個拯救瀕危物種的情境」，是搜尋過程發現這樣分數比較高。
>
> 容易混淆的地方：有些優化器會把分數或回饋放進**優化器自己的** prompt。例如 OPRO 的元提示列出過去指令和分數（p.24），GEPA 把回饋文字交給反思用的 LM（p.65）。那是給「寫 prompt 的 LLM」看的，不是最後部署的 prompt。

### 2. 少樣本優化（p.12–22）

不改 prompt 的指令，只挑選與排列放進 prompt 的範例，甚至讓模型自己產生帶推理的範例。p.14 引用 GPT-3 論文（arXiv 2005.14165）的示意圖：在 prompt 裡放幾個「輸入 → 輸出」範例，模型就能照著做新的題目，不需要更新權重。

- **範例順序也會影響結果（p.15–18）**：同樣的範例換個順序，準確率可能差 10 分以上。Lu et al. 的挑法是讓模型預測一組自己生成的句子，避開「全部預測成同一類」的順序，因為那代表這個順序讓模型有偏見。
- **自舉推理（p.19–22）**：範例通常只有答案、沒有推理，那就讓模型自己寫推理，答對的留下來當範例（DSPy），或拿去微調（STaR）。模型自己產生的推理，效果不輸人寫的。這也是 MIPROv2 步驟 ① 的做法。

### 3. 反思式優化（p.23–69）

讓 LLM 看過去的嘗試與結果，自己寫出更好的指令。

**LLM 當優化器：OPRO（p.24–25）**

讓 LLM 看過去的指令和分數，再寫一條分數更高的新指令。p.3 投票的答案：LLM 搜出來的「Take a deep breath and work on this problem step-by-step.」（80.2）比人寫的「Let's think step by step.」（71.8）高 8 分。意思差不多的句子差這麼多，人很難猜到哪句好，所以交給搜尋。

**MIPROv2 三步驟（p.26–63）**

| 步驟 | 做什麼 | 頁碼 |
|---|---|---|
| ① 自舉示範 | 把訓練範例跑過程式，通過指標的軌跡（含推理）留下當少樣本範例 | p.27–34 |
| ② 有根據的指令提案 | 把程式摘要、資料摘要、成功軌跡、一條提示技巧交給「提案用的 LM」，寫出候選指令 | p.35–47 |
| ③ 搜尋組合 | 用貝氏代理模型反覆抽「哪條指令 × 哪組示範」，在小批次上評分、更新信念 | p.48–62 |

- 步驟 ② 每次隨機給一條**提示技巧**（p.44），例如「加入高風險情境」「給模型一個角色」，讓候選指令更多樣。最後勝出的指令（p.63）正是「高風險情境」版：「為了拯救瀕臨滅絕的稀有鳶尾花，預測品種」。這種指令人不會想寫，但搜出來分數最好。
- p.43 留下的示範軌跡，推理其實是錯的，只是最後答案對。**自舉法只看結果，不保證推理正確。**

**TextGrad（p.64）**：把「這裡可以怎麼改」的文字回饋，像反向傳播一樣往回傳到各個 prompt。

**GEPA：基因–帕累托式的 prompt 演化（p.65）**

1. 維護一個候選 prompt 池，記錄每個候選在每一題上的分數。
2. **帕累托過濾**：只要候選在至少一題上是最好的，就留下。不只保留平均最好的，讓搜尋維持多樣性，不會太早收斂。
3. 產生新候選，有兩種方式：
   - **反思式突變**：挑一個候選跑幾題，把執行過程和文字回饋交給 LLM 反思，寫出改進的 prompt。
   - **系統感知合併**：挑兩個候選，每個模組各取演化過的那個版本。
4. 新候選在小批次上有進步，才做完整評估、加入候選池。重複到預算用完。

和 MIPROv2 的差別：GEPA 的 LLM 看得到**為什麼失敗**的文字回饋，不只是一個分數。

**GEPA 實例：PAPILLON（p.66–68）**

PAPILLON 讓本地小模型先把問題裡的個資拿掉，再送給外部大模型。GEPA 優化這個「改寫」prompt，分數從 82 升到 97.6，每一代都是從失敗案例反思出更細的隱私規則。整體結果 GEPA 勝過 MIPROv2 與 TextGrad（p.68）。

**上下文優化小結（p.69）**：兩種強力模式，一是自舉範例再搜尋組合，二是「跑任務 → 反思 → 改 prompt」。

### 4. 權重優化（p.70–104）

直接改模型參數的三條路：監督式微調（SFT）、強化學習（RL）、on-policy 蒸餾。

**agent 的 SFT（p.74–75）**

讓老師模型做 agent 任務，把它完成的軌跡（想法＋指令＋觀察）拿來訓練學生，學生逐 token 模仿。重點是任務和環境要夠多樣；也可以先驗證，只留成功的軌跡。

**OpenThoughts-Agent（p.76–77）**：把產生這種資料的流程拆成六階段（選任務 → 產生 rollout → 過濾 → 選老師……），每階段都做了實驗，後面「Agent 資料」講次會詳談。結論是老師軌跡越多學生越強，到 100K 筆還沒飽和。

**FireAct（p.78–79）**：用 GPT-4 跑出答對的軌跡來微調 Llama-2，微調後的 Llama-2-13B（34.4）贏過只用 prompt 的 GPT-3.5（31.4）。

> **Q：不知道這的重點**
>
> 重點是一句話：**用強老師的軌跡微調後，小模型可以贏過沒微調的大模型。** 表裡要看的是交叉比較：微調後的 Llama-2-13B（34.4）高於只用 prompt 的 GPT-3.5（31.4）。
>
> 它在這講裡的位置：
>
> | | OpenThoughts-Agent（p.76–77） | FireAct（p.78–79） |
> |---|---|---|
> | 證明了什麼 | 老師軌跡**越多**，學生越強 | 老師軌跡能讓**小模型**超過更大的模型 |
> | 對應的選擇理由 | p.120：權重優化吃得下大量資料 | p.122：有強老師、想要便宜的模型時，蒸餾進學生 |
>
> 另一個小重點：訓練資料混了三種推理方式，微調後的模型會自己挑，簡單題就直接作答，不必每題都走完整的 ReAct 迴圈。
>
> 兩篇都是「agent 的 SFT」（p.74）的實例。下一步就是 RL：不再模仿老師，改由學生自己嘗試。

**agent 的強化學習（p.80–82）**

學生自己做任務，成功就給獎勵。關鍵是**可驗證性**：要能自動判斷任務完成沒有，例如比對輸出檔和標準答案（p.82）。和 SFT 對照：SFT 每個 token 都有目標；RL 整段只有最後一個分數，軌跡是學生自己產生的。

**PPO 的流程與成本（p.83–87）**

PPO 除了要訓練的策略模型，還要三個輔助模型：參考模型（限制別偏離太遠）、獎勵模型（整段打一個分數）、價值模型（估計每個 token 值多少，用來算「這個 token 比平均好多少」的優勢）。

所以它很貴：記憶體要放 4 個模型、每步要訓練 2 個（策略和價值）、而且很多計算是逐 token 做的。

**GRPO：用群組取代價值模型（p.88–93）**

同一題抽一組輸出，各自拿一個獎勵，用組內互相比較來算優勢，就不需要價值模型。

| | PPO | GRPO |
|---|---|---|
| 記憶體中的模型 | 4（策略、參考、獎勵、價值） | 3（策略、參考、獎勵） |
| 每步要訓練的模型 | 2 | 1 |
| 逐 token 的計算 | KL、價值、優勢 | 只有 KL |

- 優勢 ＝（自己的獎勵 − 組平均）÷ 組標準差（p.92）。比同組好就加強，比同組差就壓低。
- 一組全對或全錯時，大家優勢都是 0，這題學不到東西。所以 RL 的題目要落在模型「有時對、有時錯」的難度。
- DeepSeek-R1 就是用 GRPO 訓練的，而且和 SFT 交替使用（p.94–95）。

**On-policy 蒸餾（p.96–103）**

比喻：在你自己下過的棋局上接受指導，比看別人下棋更有用。

| 方法 | 軌跡由誰產生 | 訊號 |
|---|---|---|
| SFT | 別人（off-policy） | 密集：每個 token 都有目標 |
| RL | 學生自己（on-policy） | 稀疏：整段一個分數 |
| On-policy 蒸餾 | 學生自己（on-policy） | 密集：老師替學生寫的每個 token 打分 |

學生自己寫回答，老師逐 token 打分，老師覺得不該寫的 token 懲罰越大（p.100）。Qwen3 的實驗裡，它比 RL 省約 10 倍算力，分數還更高（p.103）。

**權重優化小結（p.104）**

| 方法 | 軌跡來源 | 學習訊號 | 訓練目標 |
|---|---|---|---|
| 監督式微調 | 蒐集來的示範 | 參考的 token 與動作 | 最大化示範行為的機率 |
| 強化學習 | 學生自己產生的軌跡 | 任務獎勵 | 最大化期望獎勵 |
| On-policy 蒸餾 | 學生自己產生的軌跡 | 老師在學生前綴上的 token 機率 | 在學生軌跡上最小化與老師的差距 |

記這張表就夠了：三種方法的差別只在「軌跡誰產生」和「訊號從哪來」。

### 5. 用 agent 做優化（p.105–116）

三個例子是同一個迴圈：**改一點 → 跑評測 → 進步就留、沒進步就丟**，只是改的東西不同。

| 例子 | 誰改、改什麼 |
|---|---|
| DGM（p.106–109） | coding agent 改自己的程式 |
| Meta-Harness（p.110–111） | 另一個 meta agent 改目標 agent 的 harness |
| autoresearch（p.112–115） | agent 改模型的訓練腳本 |

**Meta-Harness** 的特點是把所有過去的程式碼、推理軌跡、分數都存在檔案系統，meta agent 每次都讀完整歷史再提新 harness，不是只看分數。它做出的 harness 贏過人寫的（p.111）。

**小結（p.116）**：agent 是很強的優化器，所以**指標成了最需要守好的部分**：指標寫錯，它會很有效率地往錯的方向優化。autoresearch 最後保留的「改進」之一是換隨機種子，就是把雜訊當成進步。

### 6. 該用哪種策略（p.117–122）

**BetterTogether：prompt 和權重交替優化（p.118）**

兩種優化不是二選一，可以交替：先優化 prompt，再微調權重，最後再優化一次 prompt。在小模型上，組合策略通常比只做其中一種好，但最佳順序依任務而異。

**樣本效率 vs 資料規模（p.119–120）**：上下文優化省樣本（GEPA 用約 7,000 次 rollout 就勝過用約 24,000 次的 GRPO）；權重優化吃得下大量資料，上限更高。

**什麼時候用上下文優化、什麼時候用權重優化（p.121–122）**

| 選上下文優化，當……（p.121） | 選權重優化，當……（p.122） |
|---|---|
| 只能用 API 的模型：有些強模型不開放微調 | 上下文優化失敗：小模型有時幾乎不會照指令做 |
| 需要頻繁、快速地重跑優化：上下文優化比較快，基礎設施也簡單 | 有能力強的老師、想要便宜的模型：直接蒸餾進學生模型通常有效 |
| 與環境互動很貴：上下文優化比較省樣本 | 上下文太長：prompt 優化會讓 prompt 越來越複雜，改用權重優化可避免上下文膨脹 |
