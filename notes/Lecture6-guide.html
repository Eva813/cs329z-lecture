提示鏈與路由 Prompt Chaining · Routing

  • 提示鏈（p.16）：把大任務拆成一連串小步驟。這是用延遲換準確度：多了幾次呼叫，但每次只做一件簡單的事。適合複雜、拆開會更好做的任務。
  • 路由（p.17）：先把輸入分類，再交給適合的 LLM，可以是不同模型，也可以是不同 prompt。適合一個大任務底下有幾種要分開處理的類別。
  • 路由也能省錢、省時間：簡單的情況交給較弱、較便宜的模型。

兩張圖都出自〈Building Effective Agents〉，原文對每個模式都有附例子，例如提示鏈的「先寫行銷文案，再翻譯」。

18–19

平行化與協調者–工作者 Parallelization · Orchestrator-Workers

  • 平行化有兩種（p.18）：
    • 分段 Sectioning：把獨立的工作拆開同時做，例如一邊判斷查詢是否安全、一邊處理這個查詢。
    • 投票 Voting：一種推論時擴展（inference-time scaling），把同一個輸入跑好幾次，再由彙整者做最後結論。
  • 平行化的好處是讓每次呼叫只專注一個面向。
  • 協調者–工作者（p.19）：一個 LLM 動態拆解任務，再分派給工作者 LLM。和平行化很像，差別在子任務是執行時才動態產生的，適合事先難以預料要拆成哪些、幾個子任務的情況。
sectioning分段voting投票inference-time scaling推論時擴展aggregator彙整者

20

評估者–優化者 Evaluator-Optimizer

輸入→LLM 產生者→LLM 評估者→通過 → 輸出
  • 一個 LLM 產生回答，另一個 LLM 給評估和回饋，形成迴圈：被退回時附上回饋，產生者再改。
  • 要成立有兩個必要條件：(1) 回饋要清楚、說得出來；(2) 有 LLM 能給出這種回饋。
  • 另外，產生者也要真的能根據回饋改進。

這三個條件在 Part 3 會再出現：Reflexion 和 CRITIC 有效，是因為回饋來自外部環境或工具；純粹讓模型自己評自己，第 (2) 個條件常常不成立（p.41）。

ReAct：先推理再行動 ReAct (2023) · Reason + Act重點

關鍵想法：在採取行動前先推理。p.34 用一題 HotpotQA 比較四種做法：「除了 Apple Remote，還有什麼裝置能控制 Apple Remote 原本設計要搭配的程式？」

標準直接回答「iPod」✗
只推理 CoT憑記憶推理，以為是 Apple TV，答「iPhone、iPad、iPod Touch」✗
只行動 Act搜尋 Apple Remote → 搜 Front Row 找不到 → 搜 Front Row (software) → 卻答「yes」✗
ReAct想：先查 Apple Remote → 得知它原本控制 Front Row → 想：查 Front Row → 找不到，改查 Front Row (software) → 得知可用 Apple Remote 或鍵盤功能鍵控制 → 回答「keyboard function keys」✓
  • p.35：原論文發現要微調才有最好的效果。只用 prompt 時，8B 小模型的 ReAct 表現最差；微調後 8B、62B 的 ReAct 都是四種方法中最好的。現在在後訓練階段微調模型扮演 agent 已經是常態。
  • p.36（PaLM-540B，HotpotQA EM／FEVER 準確率）：ReAct 27.4／60.9，高於只行動的 Act 25.7／58.9，說明行動前先推理有幫助。最好的是兩者搭配：ReAct→CoT-SC 在 HotpotQA 得 35.1，CoT-SC→ReAct 在 FEVER 得 64.6。
  • 在行動前先寫出想法，到今天仍然非常普遍。

補充：表上單用 ReAct 在 HotpotQA 其實略低於 CoT（27.4 vs 29.4），原論文的解釋是搜尋結果不一定有用，推理容易被打斷；所以才提出在兩者之間切換。

Reflexion：把反思變成記憶 Reflexion (2023)重點

關鍵想法：自我反思有用。p.38 的架構與演算法：

Actor 執行一次→Evaluator 評分→Self-reflection 寫反思→存進長期記憶→Actor 再試
  • 三個 LM：行動者 Ma、評估者 Me、自我反思者 Msr。行動軌跡是短期記憶，反思文字是長期記憶（mem）。重複「產生軌跡 → 評估 → 產生反思 → 加進 mem」，直到評估通過或到達最大次數。
  • 核心：把評估和反思轉成行動者的「記憶」，也就是上下文。模型權重不變，改的是下一次看到的 prompt。
  • p.39 三個例子：決策（以為鍋子在爐子 1，其實不在 → 下次去爐子 2）、寫程式（自己生成的單元測試沒過 → 發現只檢查了括號數量、沒檢查順序）、推理（環境回饋 0 分 → 反思「誤以為兩人都有多重職業」）。
  • p.40 左：HotpotQA 上，ReAct+Reflexion 隨嘗試次數從約 0.32 升到約 0.54；CoT+Reflexion 升到約 0.40；沒有反思的基準幾乎不動。
  • p.40 右：只給上一輪軌跡（EPM）從 0.61 升到 0.66，再加反思到 0.74。有幫助的是 LLM 的反思，不只是過去的軌跡。

自我反思的限制與 CRITIC Limitations of Self-Reflection · CRITIC (2024)

  • p.41 引用〈Large Language Models Cannot Self-Correct Reasoning Yet〉（Google DeepMind）：叫 LLM 評自己的回答，反而會讓表現變差。表中 GPT-4-Turbo 標準提示在 GSM8K 得 91.5、CommonSenseQA 84.0；換三種「請檢查你的答案」提示自我修正後，分數都持平或下降（例如 CommonSenseQA 降到 74.5–83.5）。
  • Reflexion 避開這個問題的方法，是用外部環境的回饋（測試結果、環境獎勵），而不是模型自己的判斷。
  • 這個發現早於推理模型。推理模型在推理過程中展現了不錯的自我修正能力，所以今天自我反思通常內建在 LLM 的推理裡，不再需要外部強制。
  • p.42 CRITIC：讓驗證者也能用外部工具（搜尋引擎、程式直譯器、計算機、維基百科等），變成一個「agent 式驗證者」。AmbigNQ 上 CRITIC 的 F1 隨修正輪數從約 64 升到約 75；拿掉工具（CRITIC w/o Tool）只到約 67。

回到 p.20 的兩個必要條件：回饋要清楚、要有東西能給出回饋。外部工具和環境就是讓這兩個條件成立的方法。（註：p.42 標示的出處和 p.41 相同，是 2310.01798；CRITIC 論文本身是 Gou et al., arXiv 2305.11738。）

CodeAct：用程式碼當行動 CodeAct (2024) · JSON Actions vs Code Actions重點

關鍵想法：程式碼是行動最合適的形式。p.44–45 用同一題比較：「在美國、日本、德國、印度中，找出買手機型號 CodeAct 1 最划算的國家。」可用 5 個 API：查匯率與稅率、查手機價格、換算含稅價、估運費、算最終價格。

JSON 行動每次只能呼叫一個工具：{"tool": "lookup_rates", "country": "Germany"} → 1.1, 0.19 → 查價格 → 700 → 換算含稅價 → 916.3 → …對每個國家重複一遍
程式碼行動一次寫完：for country in countries: 迴圈裡依序呼叫五個 API，最後 min(final_prices, key=final_prices.get) 找最便宜的
結果兩者都答日本，904.00 美元；但程式碼版需要的行動次數少很多
  • p.45 圖上的兩個標註說出優勢：程式碼的控制流程與資料流（迴圈、變數）讓複雜操作變簡單；還能直接重用現有軟體，例如 Python 內建的 min。

KV cacheKV 快取模型對已處理 token 的中間結果；前綴不變才能重用
event log / event stream事件日誌／事件流照實記錄所有行動與觀察，每次從中重建上下文
memory offloading記憶卸載把資訊存到外部記憶，才能從上下文刪掉
compaction壓縮用 LLM 把舊歷史摘要成較短的描述
observation masking觀察遮蔽把舊的工具輸出隱藏或截短
context isolation上下文隔離讓子 agent 只拿到自己任務需要的上下文
progressive disclosure漸進揭露先只給摘要，需要時才載入完整內容（如 skill 檔）
harness執行框架包在 LLM 外面，提供工具、上下文管理和執行環境的程式
permission check權限檢查執行危險操作前先請使用者確認
