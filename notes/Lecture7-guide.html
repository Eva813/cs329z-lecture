PART 1 · p.8–13 · 5 分鐘

為什麼 agent 需要記憶

先列沒有記憶會失去的三樣東西，再列有記憶能得到的三樣好處，各配一篇論文例子。

9–10

沒有記憶的問題，與記憶帶來的好處 重點 Problems without memory · Benefits of Agent Memory

沒有記憶會失去有記憶能得到
程序：每次都得重新教 agent 怎麼做這個任務從經驗學習：在一個 session 學到的技能，之後可以再用
知識：重要的事實、規則、偏好在 session 之間遺失個人化：agent 能學會你的個人偏好
進度：session 拉長後，agent 忘了自己做過什麼、先前的目標和指示狀態延續：新對話能接著上次繼續，例如「把我們上次在寫的提案打開」

左右兩欄是一一對應的：程序 ↔ 從經驗學習、知識 ↔ 個人化、進度 ↔ 狀態延續。後面的記憶類型（p.17–20）也大致照這個分法。

session對話階段（一次獨立的對話或任務）personalization個人化statefulness狀態延續
Effective Harnesses for Long-Running Agents（跨 session 保留進度的實作）
11–13

三個好處的論文例子 Personalization · Learning from experience · Statefulness

  • 個人化（p.11，PersonaMem，Jiang et al., 2025）：使用者在第 2 次對話說愛吃義大利菜，第 12 次說發現自己麩質過敏、改吃地中海料理，第 20 次問「今晚煮什麼」。好的回答會推薦無麩質的地中海海鮮；壞的回答是「我記得你愛義大利菜，要不要做義大利麵？」——記得舊偏好，卻沒跟上更新。
  • 從經驗學習（p.12，Agent Workflow Memory，Wang et al., 2024）：先學會「在地圖上找地點」的步驟，之後「查某地郵遞區號」就直接沿用前幾步，再加上新步驟，逐步累積出更複雜的 workflow。Part 4 會詳細講。
  • 狀態延續（p.13，Du et al., 2025）：使用者說「我準備好完成上次討論的機票訂位了」。沒有跨 session 記憶時，agent 得重新問出發地、目的地、日期……要 10 輪；有記憶時，檢索器取回「舊金山 → 雪梨、聯合航空、經濟艙」，2 輪就確認完成。
PersonaMem、AWM、Du et al. 本站未收錄：arXiv 2504.14225、2409.07429、2505.20231

回顧：agent 記憶的類型

用 CoALA 框架把記憶分成四類，再從「存在權重裡還是放進上下文」切另一刀。

15–16

CoALA：語言 agent 的認知架構 重點 Cognitive Architectures for Language Agents · Sumers et al., 2024

  • CoALA 借用認知科學的分類來描述語言 agent。p.16 的架構圖分成三塊：
  • 長期記憶：程序記憶（LLM 本身＋agent 程式碼）、語意記憶（資料庫圖示）、情節記憶（文件堆圖示）。每一種都有「檢索（Retrieval）」箭頭往下讀、「學習（Learning）」箭頭往上寫。
  • 工作記憶：中間的大方塊，裡面是推理（Reasoning）迴圈；程序記憶透過 Prompt／Parse 和它交換資料。
  • 決策程序：左下的決策樹，決定下一步；對外產生行動、接收觀察，外部環境分成對話、實體世界、數位環境三種。

情節記憶 Episodic Memory

  • agent 過去行為的序列，也就是軌跡（trajectory）。在聊天機器人裡，就是所有過去對話的紀錄。
  • 通常是原始日誌，照實記下發生了什麼，不加整理。

語意記憶 Semantic Memory

  • 儲存關於世界的事實：使用者的資料、偏好、一般知識，都算語意記憶。
  • 一般人說「聊天機器人有記憶」，通常指的就是這一種。

設計記憶的三個問題，與三種儲存方式

先列出設計記憶系統要回答的三題，再介紹底層三種儲存，最後預告四種架構模式。

24

關鍵問題：What、When、How 重點 Key Questions: What, When, and How?

問題常見答案
What：要存進／取出什麼？事實（具體的與一般的）、程序、對話進展……
When：什麼時候觸發存取？agent 透過工具隨需呼叫、背景工作程序、事件驅動……
How：用什麼方式存取？檔案系統、資料庫（檢索）、知識圖譜……

讀後面每個架構時，都可以回頭問這三題。例如 MemGPT：What＝事實與對話；When＝agent 用工具自己決定；How＝向量資料庫＋字串／日期查詢。

儲存方式一：檔案系統 How: Three Systems for Memory · Filesystem

  • p.25：記憶最終得存到磁碟上，最常見的三種做法是檔案系統、資料庫、知識圖譜。
  • 每筆記憶就是一個檔案，可以讓 agent 自己管理；資料夾天生帶來階層結構；grep、ls 等 bash 指令就是記憶工具。
  • 配圖（LangChain 部落格）把三類記憶對到檔案：程序記憶 → AGENTS.md、mcp.json；語意記憶 → foo/SKILL.md、bar/knowledge1.md；情節記憶 → conversations/01_10_2025.json。

Part 8 的 LongMemEval-v2 結果（p.85）顯示，檔案系統式記憶在那個基準上勝過檢索式記憶。

儲存方式三：知識圖譜 Memory System: Knowledge Graph · Rasmussen et al., 2025 (Zep)

  • 把記憶存成「實體—關係—實體」的圖，例如「人 —在…工作（至 2026 年 3 月）→ 公司」「人 —關心→ 主題」「人 —使用→ 產品」。關係可以帶時效。
  • Zep 的記憶分三層：第 1 層情節（原始文件、對話、JSON）→ 第 2 層實體與關係 → 第 3 層社群（實體的群集與它們的摘要）。

模式一：從經驗學程序

把成功的做法存成可重用的程式、workflow 或 skill 檔，下次遇到類似任務直接拿出來用。

31–34

Voyager 與技能庫 重點 Voyager · Skill Library · Wang et al., 2023

  • Voyager 是在 Minecraft 裡持續探索的 agent，有三個元件（p.31）：自動課程（依探索進度提出新任務，如砍樹 → 做工作台 → 打殭屍 → 挖鑽石）、迭代提示（GPT-4 寫 JavaScript 程式當行動，依環境回饋、執行錯誤與自我驗證修改）、技能庫。
  • 技能怎麼存取（p.32）：程式通過自我驗證後，用 GPT-3.5 為它寫一段說明，說明的嵌入向量當 key、程式本身當 value 存進技能庫。新任務（如「做鐵鎬」）時，先讓 GPT-3.5 產生做法說明，再用它的嵌入取回最相關的 5 個技能（熔鐵錠、做木棍、做工作台……）。

Agent Workflow Memory（AWM） AWM · Inducing the "Workflows" · Results · Wang et al., 2024

  • 流程（p.35）：① agent 執行任務取得行動軌跡（例如「誰下了訂單 #0130？」→ 點「Orders」→ 捲動 → 回報「Emma Lopez」）；② 評估軌跡是否正確解題；③ 正確的話，從中歸納出 workflow（說明＋步驟），整合進記憶。
  • 歸納用的 prompt（p.36）：「給你一批網頁導覽任務，請抽取共同的 workflow」——每個 workflow 是常被重用的子程序、至少兩步、不要重複，會變動的部分（輸入文字、按鈕名稱）用有意義的變數名代替。
  • 產出的 workflow（p.37）像「購物：瀏覽特定分類的商品」→ hover('main_category_id')、click('subcategory_id')。這些 workflow 會放進系統提示，當作解題時的上下文。
  • 結果（p.38，WebArena 跨模板子集）：AWM 總成功率 33.2%，高於純自主 agent 的 AutoEval 23.2%、BrowserGym 20.5%，也略高於使用人工設計 workflow 的 SteP 32.1%。學習曲線顯示約 40 個查詢後就進入穩定期。

模式二：分層記憶

MemoryOS：短、中、長期三層 MemoryOS · Kang et al., 2025

  • 短期記憶（STM）：以「頁」為單位的 FIFO 佇列，存最近的對話輪。滿了就把舊頁推進中期記憶。
  • 中期記憶（MTM）：把相關的頁串成「對話鏈」，再組成段落（segment）。每段有熱度，熱度超過門檻 τ 就更新到長期記憶；冷掉的段落會被刪除。
  • 長期人設記憶（LPM）：分使用者人設與 agent 人設，包括使用者知識庫、使用者特質（動態）、使用者／agent 檔案（靜態）。
  • 回答時從三層各取一部分：STM 全部、MTM 的前 k 頁、相關的 LPM，合起來生成回應。

和 MemGPT 比，MemoryOS 的換層是規則驅動（FIFO、熱度門檻），不是讓 LLM 自己呼叫工具決定。

MemoryArena：在多 session 任務中真正用上記憶 MemoryArena · He et al., 2026

  • p.88：評估形式是「記憶—agent—環境」迴圈。每個 session 處理一個子任務：取回記憶與子任務指示 → agent 在環境中行動 → 環境回饋 → 記憶系統整理、更新。
  • p.89–90 四種環境，子任務彼此依賴：組合購物（先買相機，再買相容且評價最高的鏡頭）、團體旅遊規劃（Tracy 排好 5 天德州行程，Chelsea 加入、預算多 150 美元、第三天想吃評分 4.5 以上的韓式烤肉……）、漸進式網路搜尋（逐步加條件找人）、形式推理（數學、物理，後一題用到前一題的推導）。
  • p.91 結果（任務 agent 為 gpt-5.1-mini，平均成功率）：長上下文 0.09–0.19；記憶 agent（Letta、Mem0、Mirix、Mem0-g、Reasoning Bank）0.12–0.14；RAG 0.17–0.20（text-embedding-3-small 最高 0.20）。團體旅遊規劃的成功率全部是 0.00。
  • 投影片結論：記憶控制器在這裡是最弱的方法，進步空間很大。不過這是真實又複雜的任務，失敗不能全歸咎於記憶。

p.92：四項條件全部通過（四個真實環境；軌跡數十萬 token；要滿足許多累積的限制條件；限制條件可驗證）。

三個尚未解決的問題：記什麼、忘什麼；信任與隱私；記憶用得恰當。

96–97

記什麼、忘什麼 重點 Challenges · Choosing what to remember and what to forget · Ma et al., 2026

  • p.96 三個挑戰總覽：記什麼與忘什麼（建立記憶時不知道未來是否相關）；信任、隱私與使用者控制（記憶是 agent 的攻擊面，使用者記憶也牽涉隱私）；正確使用記憶（誤用記憶造成過度個人化）。
  • 建立記憶時無法知道它未來是否有用。全部保留會增加檢索、上下文與維護成本；忘掉又可能丟失有用的證據或還沒兌現的承諾。

信任、隱私與使用者控制 Trust, Privacy, and User Control · Chen et al., 2024 · Shao et al., 2025

  • p.98 AgentPoison：攻擊者在 agent 的記憶或 RAG 知識庫裡植入少量惡意示範，並最佳化一個觸發詞。使用者的指令一旦帶有觸發詞（例如「帶我去機場，開得平順安全」），就會取回惡意示範，讓自駕 agent 做出「突然停車、全力煞車」的危險動作。投影片：可以誘使模型依被下毒的程序記憶做出危險行為。
  • p.99 PrivacyLens：agent 在不完全理解你想保密什麼的情況下與外界互動，帶著記憶時更可能洩漏個人細節。例：John 請 agent 寄週報給主管，agent 從行事曆讀到「和 TechAdvance 招募人員午餐」，就把它寫進週報——對主管洩漏了他在找工作。

正確使用記憶：過度個人化 Using Memory Correctly · Hu et al., 2026

  • LLM 有時太急著使用上下文裡的東西。可以靠更好的檢索，或訓練 LLM 忽略不重要的上下文來改善，但兩者都還沒完全解決。
  • 不同使用者對個人化的接受度也不一樣。
  • 例：使用者 Evan 問「年輕選民在未來選舉中扮演什麼角色？」，取回的記憶是「在做健康的小改變」「有小孩」等無關內容。模型卻回「就像你在生活中做健康的小改變，每一張年輕選票也是邁向改變的小勝利」，還問「你的孩子開始關心這些議題了嗎？」——過度個人化分數 0.5。
