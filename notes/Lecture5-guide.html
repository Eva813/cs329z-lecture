簽名：從一行字串到 Signature 類別 Signatures (demo backup)重點

四個例子，由簡到繁：

# p.25 最簡單：字串簽名
chat = dspy.Predict("message -> response")

# p.26 結構化輸出
dspy.Predict("message -> sentiment")

# p.27 加上型別
dspy.Predict("message: str -> sentiment: Literal['positive','negative','neutral'], confidence: float")

# p.28 複雜時改用類別
class ExtractEvent(dspy.Signature):
    """Extract event details from an email."""
    email: str = dspy.InputField()
    event_name: str | None = dspy.OutputField()
    date: dt.date | None = dspy.OutputField()
    start: dt.time | None = dspy.OutputField(desc="24-hour clock")
    duration_minutes: int | None = dspy.OutputField(desc="duration of the event…")
  • p.26 的輸出是 positive、Negative、negative，大小寫不一致。投影片註記「格式不統一不太好」，這正是 p.27 要加型別的原因。
  • p.27 加上 Literal[...] 後，輸出一律是三個值之一，還多了信心分數（例如 0.98、0.9、0.86）。
  • p.28 用類別定義後，輸入「這週五 10 月 9 日上午 10 點 PST 有會議」，得到 date=2026-10-09、start=10:00；email 沒寫長度，duration_minutes=None。

這和 Lecture 2 的結構化輸出、Lecture 4 的 JSON schema 是同一件事：用型別約束模型的輸出。差別在 DSPy 讓你只寫型別，prompt 由框架產生。

模組：換推論策略，組合多次呼叫 Modules (demo backup)重點

  • p.30 換推論策略：把 dspy.Predict 換成 dspy.ChainOfThought，簽名不用改，輸出多了一個 reasoning 欄位。
  • p.31 再定義第二個小簽名 PickEmoji：輸入活動名稱，輸出一個 emoji。例如「Dentist」→ 🦷。
  • p.32 組合：寫一個 dspy.Module，裡面兩次 LLM 呼叫，中間夾普通 Python 邏輯：
class UpdateCalendarFromEmail(dspy.Module):
    def __init__(self):
        self.extract = dspy.ChainOfThought(ExtractEvent)   # LLM 呼叫 1
        self.pick_emoji = dspy.ChainOfThought(PickEmoji)   # LLM 呼叫 2

    def forward(self, email):
        details = self.extract(email=email)
        if details.event_name is None or details.date is None or details.start is None:
            return dspy.Prediction(event=None, status="no event found in email")  # 一般 Python 控制流程
        emoji = self.pick_emoji(event_name=details.event_name).emoji
        event = tinycal.add_event(...)
        return dspy.Prediction(event=event, status="added to calendar")
輸入 1「這週五 10 月 9 日上午 10 點有會議」→ added to calendar
輸入 2「謝謝你寄投影片，看起來很棒！」→ no event found in email（沒有活動，不加）

優化器：用 GEPA 讓小模型從 55% 變 100% Optimizers: The Data · The Metric (demo backup)重點

p.36 重放三根支柱：優化需要資料和指標。接著分六步：

① 資料→② 指標→大模型先驗證→③④ 小模型基準→⑤ GEPA 優化→⑥ 再評一次
  • ① 資料（p.37–38）：50 封擬真 email，每封有標準答案。例如「Jesse 剪髮，2026 年 10 月 28 日下午 2:45，一小時」→ {'date': '2026-10-28', 'start': '14:45', 'duration_minutes': 60}。轉成 dspy.Example，輸入是 email，其餘是標籤；打亂後切 30 筆訓練、20 筆測試。
  • ② 指標（p.39）：日期、開始時間、長度三者全對才得 1 分，否則 0 分。活動名稱是自由文字，不評分。指標還會回傳文字回饋（例如「date: expected …, got …」），GEPA 會把這段給反思模型看。
  • 驗證（p.40）：大模型（程式註解寫 gpt-5.4-nano，是 demo 的預設 LM）在 20 筆測試上 20/20 = 100%。
  • ③④ 小模型（p.41）：同一個簽名換成 Gemma 3 12B，優化前 11/20 = 55%。
  • ⑤ 優化（p.42）：dspy.GEPA(metric=event_metric, max_metric_calls=100, reflection_lm=dspy_llm)，約 3 分鐘。大模型負責反思小模型的錯誤，被調整的是小模型的 prompt。
  • ⑥ 結果（p.43）：小模型優化後 20/20 = 100%。（55% → 100%，我驗算過：11/20 = 0.55）
  • p.44：GEPA 唯一改動的是指令文字。印出來是一份很長的說明：輸入可能長怎樣、各欄位要什麼格式（日期用 YYYY-MM-DD、沒寫時區就用 UTC）、常見陷阱等。

回到 p.4 的比喻：這就是 prompt 版的 optimizer.step()。你不手改 prompt，而是給資料和指標，讓框架去改。

# p.61 結構化輸出：用 Pydantic 定義（對照 DSPy 的 Signature 類別）
class ExtractEvent(BaseModel):
    event_name: str | None = Field(description="short title for the event…")
    date: dt.date | None
    start: dt.time | None = Field(description="24-hour clock")
    duration_minutes: int | None = Field(...)
extract_llm = langchain_llm.with_structured_output(ExtractEvent)

# p.62 狀態
class State(TypedDict):
    email: str
    details: ExtractEvent | None

# p.63 節點：讀狀態、計算、只回傳改了的部分
def extract(state: State):
    return {"details": extract_llm.invoke(state["email"])}

# p.64 組圖
builder = StateGraph(State)
builder.add_node("extract", extract)
builder.add_edge(START, "extract")
builder.add_edge("extract", END)
graph = builder.compile()

做一個可持久的 workflow Making a Durable Workflow: Activities · Workflow · Worker · Run it

# p.101 Activity：直接重用 DSPy 的模組
@activity.defn
def extract_event(email: str) -> dict | None: ...   # 呼叫 extract_cot
@activity.defn
def select_emoji(title: str) -> str: ...            # 呼叫 emoji_cot
@activity.defn
def add_to_calendar(details: dict, emoji: str) -> str: ...

# p.102 Workflow：每個可能失敗的呼叫都包一層 execute_activity
RETRY = RetryPolicy(initial_interval=timedelta(seconds=1), maximum_attempts=5)

@workflow.defn(sandboxed=False)
class CalendarWorkflow:
    @workflow.run
    async def run(self, email: str) -> str:
        details = await workflow.execute_activity(extract_event, email,
                      start_to_close_timeout=timedelta(minutes=1), retry_policy=RETRY)
        if details is None:
            return "no event found in email"
        emoji = await workflow.execute_activity(select_emoji, details["title"], ...)
        return await workflow.execute_activity(add_to_calendar, args=[details, emoji], ...)
  • workflow 本身必須是確定性的：不能自己呼叫 LLM、不能自己做 I/O，因為 Temporal 會依照記錄重播它。會變動的事都放進 activity。
  • p.103 Worker：Worker(client, task_queue="calendar", workflows=[...], activities=[...])。
  • p.104 執行兩封信：「週四 10 月 8 日下午 3 點 office hours」→ added to calendar；「謝謝投影片」→ no event found。每一步都記錄在 localhost:8233 的網頁介面。
  • p.105–106：行事曆多了週四 Office hours；Temporal 時間軸顯示 extract_event → select_emoji → add_to_calendar 依序執行。

和 p.32 的 DSPy 模組幾乎一樣，差別只在每次呼叫外面多包了「逾時 + 重試」，並且結果會被記錄。

由 server 計時：殺掉 worker 也不會丟 Server Based Orchestration · Server Based Timing重點

  • p.113 ReminderWorkflow：先跑子流程把活動加進行事曆，再 await workflow.sleep(seconds) 等到提醒時間。一個 workflow 可以一行睡上幾個月甚至幾年。
p.114啟動「週四 10/8 上午 11 點 lab meeting，60 分鐘」，設 20 秒後提醒。10 秒後把 worker 殺掉。查狀態：RUNNING（沒有任何 worker 活著，workflow 仍在執行中）
p.115重新啟動一個 worker。計時器到了，workflow 完成，印出「Reminder!」。LLM 步驟沒有重跑，因為結果已經記錄過；行事曆上只有一筆 Lab meeting，不是兩筆。
p.116–117行事曆截圖與時間軸：CalendarWorkflow 跑完後是一段 20 秒的計時器。

這就是「可持久」的意思：計時和狀態放在 server，不在你的行程裡。對 agent 來說，當機後不必從頭重跑（也不必重付 LLM 的錢），也不會重複執行有副作用的動作。

保持簡單 Keep it Simple重點

  • 你不一定需要做 agent，有時 workflow 才是對的選擇。
  • 真的要做 agent 時，仔細想清楚要給它哪些工具。
  • 如果資料很多，甚至可以端到端優化一個模型。

對照框架地圖：從左往右（模型 → workflow → agent），控制權越來越交給模型，也越難預測。能用左邊解決就不要往右走。

讓失敗看得見、救得回來 Make Failures Observable and Recoverable · Example: Shepherd

  • 追蹤模型呼叫、工具呼叫、狀態變化和錯誤。
  • 設定逾時、重試上限和執行預算。

挑戰與限制 Challenges / Limitations重點

  • 抽象讓你離底層細節更遠，所以要確定你知道底下發生什麼事。頁面配了一張迷因（出處 hamel.dev〈Fuck You, Show Me The Prompt〉）：有人說「我們的函式庫能讓 LLM 輸出最好的結果」，蝙蝠俠回「把 prompt 拿出來看」。
